# Prototype User Stories (Sprint-ready)

Format: As a <role>, I want <goal>, so that <reason>.

Priority: Must / Should / Later

---

## Auth

US-01 (Must)  
As a new user, I want to register with email and password, so that I can access the app.

US-02 (Must)  
As a newly registered user, I want to receive an email OTP, so that I can verify I own the email address.

US-03 (Must)  
As a user, I want to sign in with email/password, so that I can access my account.

US-04 (Must)  
As a user, I want to sign in with Google, so that I can access the app without creating a password.

US-05 (Should)  
As a user, I want to reset my password via email, so that I can recover my account.

US-06 (Must)  
As a user, I want one account identity concept across web and mobile, so that I don’t maintain two logins.  
(Prototype: same email identity model; real shared API later.)

---

## Navigation / Home

US-07 (Must)  
As a logged-in user, I want a home screen with Training, Academies and Store entry points, so that I can reach the main pillars quickly.

US-08 (Should)  
As a user, I want to see promotions/programmes placeholders on home, so that stakeholders can visualise the content model.

---

## Training

US-09 (Must)  
As a customer, I want to browse training offerings, so that I can find programmes.

US-10 (Must)  
As a customer, I want to view training details and register interest, so that I can apply/join.

---

## Academies

US-11 (Must)  
As a user, I want to browse academies by province, so that I can find a nearby/relevant academy.

US-12 (Must)  
As a user, I want to view academy details and submit a registration form, so that I can join/recruit.

---

## Store / Orders

US-13 (Must)  
As a customer, I want to browse products and simulate checkout, so that the store journey can be demonstrated.

US-14 (Must)  
As a customer, I want to track my order status in-app, so that I know progress after purchase.

US-15 (Should)  
As a customer, I want an order confirmation email after purchase, so that I have proof of the order.

US-16 (Should)  
As a customer, I want a payment confirmation OTP step (simulated), so that the security story from the meeting is visible.

---

## Reseller

US-17 (Must)  
As a reseller, I want a dashboard with code/earnings/clients, so that I can monitor my selling activity.

US-18 (Must)  
As a reseller, I want to see bought/pending/confirmed clients, so that I can follow up.

US-19 (Should)  
As a reseller, I want approval-by-admin before full access, so that onboarding matches the business process.

---

## Admin

US-20 (Must)  
As an ops admin, I want to approve resellers and update order statuses, so that I can run operations without developers.

US-21 (Should)  
As an ops admin, I want basic product/price/promotion edit screens, so that content management is demonstrated.

---

## Explicitly later (not current prototype Must)
- Live bank automation
- Withdrawal payouts to real accounts
- Full ambassador vetting workflow
- Final branding/colours
- Donations
